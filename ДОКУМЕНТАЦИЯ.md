# BrainPhotoTool — техническая документация

Программа обработки фото для лабораторного эксперимента (флуоресцентная
визуализация мышиных черепов/мозгов/срезов). Этот файл — техническое описание
устройства программы и история значимых решений, для разработки/отладки.
Пользовательская инструкция — отдельно, в `Как пользоваться.txt`.

## 1. Структура проекта

```
brainphoto/
  данные/                         — сырые фото по исследованиям (не код)
    README.md                     — конвенция раскладки папок для новых исследований
    <исследование>/
      <группа>/{голова, череп и мозг, срезы}/*.tif+*.xml
      результаты/                 — сводные таблицы/графики по исследованию
  brain_photo_tool/                — этот репозиторий
    src/braintool/                 — исходный код
    app_entry.py, BrainPhotoTool.spec, requirements.txt  — сборка PyInstaller
    программа/                     — готовая exe-сборка (gitignored, ~468 МБ)
    Запуск программы.lnk           — ярлык на программа/BrainPhotoTool.exe
    Как пользоваться.txt           — инструкция для не-программиста
```

`данные/` и `brain_photo_tool/` разведены сознательно: данные не должны попадать
в git, а готовая exe-сборка не должна путаться с сырыми фото. Ярлык и инструкция
лежат прямо в `brain_photo_tool/`, чтобы папку можно было передать не-специалисту
целиком («тыкай ярлык»).

При добавлении `программа/` в git-репозиторий обязательно добавлена в
`.gitignore` — она не version-control-friendly (сотни МБ бинарников).

## 2. Модель данных (`models.py`)

- `MaskMode` — `WHOLE_BLOB` (весь срез мозга целиком) или `ROSTRAL_CUT`
  (носовая/передняя часть черепа).
- `GroupConfig` — одна папка с фото одной группы животных: `mode`, `cols`
  (животных в ряд по горизонтали), `rows` (срезов на животное; `None` = определять
  автоматически по числу найденных пятен).
- `Shot` — один кадр (набор файлов с разными выдержками одного и того же вида).
- `SpecimenMask` — маска одного животного/среза: растровая маска, для
  `ROSTRAL_CUT` дополнительно `cut_line` (линия отреза, можно двигать в UI) и
  `source_blob`/`rostral_anchor` (для пересчёта маски при перетаскивании линии).
- `MeasurementRow` — одна строка измерений: `group`, `animal_index`,
  `slice_index`, `area_px`, `mean_intensity`, `std_intensity`, `source_file`,
  **`mode`** и **`exposure_ms`** (добавлены в этой сессии — см. раздел 5).

## 3. Сегментация (`segmentation.py`)

### 3.1. Обнаружение пятен — `detect_blobs()`

Единый строгий порог: медиана фона + `SEED_SIGMA_MULTIPLIER` (4.0) × устойчивый
разброс (MAD). Даёт уверенные "ядра" пятен — по их числу считается количество
животных/срезов на фото. Порог свой для каждого кадра (не Otsu на растянутой
гистограмме — тот отсекал тусклый диффузный край ткани вокруг ядра пятна на
флуоресцентных снимках).

### 3.2. Расширение до тусклого края — `grow_blob_to_soft_edge()`

Применяется ТОЛЬКО для `WHOLE_BLOB` (срезы), не для `ROSTRAL_CUT` (черепа —
геометрия чувствительна к форме пятна, см. 3.4).

У тусклых срезов сигнал плавно спадает к фону, и реальная граница ткани
(видна глазом, измеримо ещё повышена над фоном) оставалась за пределами
строгого порога — площадь занижалась, маска обрезала край. Решение —
гистерезис с ОГРАНИЧЕННЫМ радиусом роста:

1. Мягкий порог (`GROW_SIGMA_MULTIPLIER` = 1.5) — более щедрая маска.
2. `dilate(ядро, margin_px=15) ∩ мягкий_порог` — ядро расширяется до мягкого
   порога, но не дальше фиксированного радиуса вокруг себя.
3. Расширение других пятен на фото (`other_blobs`, тоже дилатированных на тот же
   `margin_px`) исключается из зоны роста — иначе спорная зона между двумя
   близкими срезами (тусклая "дымка" между ними выше мягкого порога — обычное
   дело для соседних срезов одного препарата) попадала бы в обе маски сразу
   и дублировала бы площадь/яркость. Симметричное исключение оставляет спорную
   полоску ничьей (консервативная недооценка), но без пересечения масок.

**Почему не просто гистерезисный порог по связности (без ограничения
радиуса)**: первая версия так и была сделана и сломалась на реальных фото —
мягкий порог местами недостаточно тёмный (неравномерная засветка/блики), и
маска "утекала" по связности через весь кадр в далёкий блик, разрастаясь на
треть кадра. Отсюда и ограничение фиксированным радиусом вместо чистой
связности.

### 3.3. Разделение черепов и мозгов — `assign_rostral_blobs_to_grid()` + `_split_by_largest_y_gap()`

На фото «череп и мозг» в одном кадре одновременно черепа (верхний ряд) и целые
мозги (нижний ряд) — в режиме `ROSTRAL_CUT` анализируются только черепа.

Наивный подход "взять самое верхнее пятно в каждой колонке" ломается, если у
одного черепа нос не прошёл порог (слишком тусклый) и не нашёлся как пятно —
тогда "самым верхним" в этой колонке оказывается мозг снизу.

Решение — сначала разделить ВСЕ пятна фото на верхнюю/нижнюю полосу по самому
большому разрыву по Y (`_split_by_largest_y_gap`), и только потом раскладывать
по колонкам внутри верхней полосы. Если черепа нет — колонка остаётся пустой
(доразметить вручную), а не подхватывает мозг.

Порог "заметности" разрыва — медиана ОСТАЛЬНЫХ разрывов (исключая сам
оцениваемый максимальный), умноженная на 2, минимум 30px. **Важно**: медиана
именно ОСТАЛЬНЫХ — если считать по всем разрывам включая оцениваемый, при
малом числе пятен (типично фото с одним животным, `cols=1`) медиана
самоотравляется и оказывается сопоставима с самим разрывом, из-за чего деление
почти никогда не срабатывает (баг, найденный код-ревью и исправленный).

Крайние случаи:
- **≥ 3 пятна** (≥ 2 разрывов) — медиана остальных разрывов работает надёжно.
- **Ровно 2 пятна** (типично `cols=1`) — сравнивать не с чем, делим безусловно
  (на фото «череп и мозг» с одним животным два пятна почти наверняка и есть
  пара череп+мозг).
- **1 пятно** — делить нечего; `assign_rostral_blobs_to_grid` в этом случае
  явно предупреждает пользователя ("не удалось надёжно отличить череп от
  мозга... проверьте вручную"), а не молча считает найденное пятно черепом.

Раньше сравнение шло с высотой (bbox по Y) пятна — оказалось ненадёжным:
черепа на реальных фото часто вытянуты почти на всю высоту своего ряда,
вплотную к границе с рядом мозгов (спинной мозг/срез уходит вниз), так что
высота пятна и разрыв между рядами — одного порядка величины.

### 3.4. Носовая часть черепа — `compute_rostral_cut()`

PCA по маске черепа → главная ось вытянутости → профиль ширины вдоль оси →
поиск "талии" между лицевым отделом и мозговой коробкой (`_find_rostral_boundary_bin`,
не менялась) → отрезаем всё до "талии" как носовую часть.

**Направление профиля** (какой конец считать носом) определяется знаком
Y-компоненты главной оси PCA (`main_axis[1] >= 0`) — по протоколу съёмки черепа
на этих фото ВСЕГДА лежат носом вверх (к меньшим Y на кадре). Это допущение
специфично для конкретного протокола этой лаборатории, не универсальный
алгоритм.

Раньше направление определялось сравнением средней ширины профиля в узком
окне (10% длины) на каждом конце — самый узкий конец считался носом. Ломалось,
если каудальный (задний) конец среза тоже сужался (например, если в кадр
попадает часть спинного мозга) — он мог оказаться ещё уже носа, и тогда почти
вся мозговая коробка ошибочно попадала в "носовую" обводку.

**Известное ограничение** (не исправлено, отмечено код-ревью как не
блокирующее): если пятно почти круглое (собственные значения PCA близки —
блоб слабо вытянут, например из-за слияния/шума), направление главной оси
численно неустойчиво, и результат может быть случайным без предупреждения.
Также если реальный кадр нарушает протокол (череп положен не носом вверх) —
результат будет молча неверным для этого кадра. Дешёвая защита (warning при
`eigvals[largest]/eigvals[smallest]` близко к 1, и/или sanity-check против
старого способа по ширине) не реализована.

### 3.5. `assign_blobs_to_grid()` (режим `WHOLE_BLOB`, срезы) — не менялась в этой сессии

Раскладывает пятна по сетке (животное × срез), число срезов на животное — по
умолчанию автоопределяется как максимум пятен в одном столбце.

## 4. Ручная доразметка (`canvas.py`)

`MaskCanvas` — виджет фото с полупрозрачными масками. Кисть (левая кнопка —
рисовать, правая — стирать, колесо — размер), для `ROSTRAL_CUT` дополнительно
линия отреза с двумя перетаскиваемыми ручками.

**Было**: линия отреза рисовалась и была перетаскиваемой только у активного
(выбранного) животного. На фото, где черепа лежат не по линейке, у остальных
животных линию было не видно и не поправить.

**Стало**: рисуются и перетаскиваемы ВСЕ линии сразу — активная ярко (толще,
непрозрачнее), остальные притушенно. Клик по ручке ЛЮБОЙ линии (не только
активной) сразу перетаскивает её и переключает активное животное — не нужно
сначала щёлкать по нему в списке слева.

## 5. Результаты и статистика (`measurements.py`, `review_window.py`, `stats.py`)

### 5.1. Смешение режимов в сравнении групп

Проблема: если пользователь добавляет в одном сеансе анализа И группу «череп и
мозг» (носовая площадь), И группу «срезы» (площадь среза) под ОДНИМ И ТЕМ ЖЕ
именем (разумный сценарий — анализ обоих этапов одного эксперимента разом),
их измерения — разные физические величины — молча усреднялись/сравнивались
вместе.

Решение: `MeasurementRow` получил поле `mode` (`whole_blob`/`rostral_cut`).
`per_animal_average()` группирует и по `mode` тоже (не только по группе/кадру/
животному). В `ResultsTab` добавлен выпадающий список **"Что анализируем"**,
заполняется по факту присутствующих в загруженных данных режимов — таблица и
статистика сравнения ВСЕГДА фильтруются по выбранному режиму перед
агрегацией/сравнением.

### 5.2. Несопоставимая выдержка между группами

`choose_best_exposure()` выбирает "лучшую" незасвеченную выдержку для КАЖДОГО
кадра независимо — если сравниваемые группы были сфотографированы на разной
выдержке, яркостные метрики (`mean_intensity`/`std_intensity`) могут быть
искажены (дольше выдержка — систематически выше сигнал), даже без реального
биологического различия.

Решение: `MeasurementRow` получил поле `exposure_ms` (из `shot.chosen_exposure`).
При сравнении групп по яркостной метрике, если у сравниваемых групп разный
набор выдержек — в вывод добавляется явное предупреждение с конкретными
значениями выдержки по каждой группе. Для `area_px` предупреждение не
показывается (площадь исторически считалась менее чувствительной к экспозиции
за счёт адаптивного порога, но это не строго доказано — заявление не делается).

## 6. Хронология этой рабочей сессии

1. **Реорганизация файлов** — разрозненные папки (`срезы`, `brain_photo_tool`,
   `Обработка фото мозга`) сведены в `brainphoto/{данные, brain_photo_tool}`.
   Добавлен `README.md` с конвенцией для будущих исследований.
2. **Первый раунд фиксов** (коммит `c518df2`): все линии отреза видны/
   перетаскиваемы (раздел 4); мозги исключены из анализа на фото «череп и
   мозг» (первая версия — "самое верхнее пятно в колонке"); гистерезисный
   порог для тусклых срезов (первая версия — по связности, без ограничения
   радиуса).
3. **Пользователь протестировал и сообщил о регрессиях**: блики на срезах,
   черепа выделяются "полностью", статистика "странная" (смешение), выдержка
   между группами разная.
4. **Второй раунд фиксов**: диагностика на реальных фото всех 4 групп лаборатории
   (не на одном примере — ключевой урок первого раунда), рост маски ограничен
   радиусом (раздел 3.2), разделение по Y-полосам вместо "верхнее пятно в
   колонке" (раздел 3.3, первая версия), направление носа по PCA-оси вместо
   ширины (раздел 3.4), поля `mode`/`exposure_ms` и фильтр в `ResultsTab`
   (раздел 5).
5. **Независимое код-ревью** (агент "Программист") нашло 2 реальных бага в
   правках раунда 4 ДО того, как они дошли до пользователя:
   - критично: медиана разрывов в `_split_by_largest_y_gap` самоотравлялась
     при малом числе пятен — именно тот случай, ради которого писалась защита;
   - важно: `grow_blob_to_soft_edge` исключал только ядро соседнего пятна, не
     его расширение — спорная зона между близкими срезами дублировалась в
     обеих масках (пересечение 80px на тесте ревью).
   Оба исправлены (коммит `f4d4f50`), перепроверены на тех же тестах, что
   использовал ревьюер (пересечение масок → 0px), плюс полный повторный
   прогон по всем 4 группам без регрессий.
6. Exe пересобран (PyInstaller), запущен и проверен (стартует без падения,
   ярлык рабочий).

## 7. Известные ограничения / что не сделано

- Общий редизайн UX ручной доразметки (навигация/зум при рисовании кистью) —
  из исходного списка задач пользователя, отложен на будущее.
- `compute_rostral_cut`: нет защиты от слабо вытянутых (почти круглых) пятен
  и нет sanity-проверки против нарушения протокола (череп положен не носом
  вверх на конкретном кадре) — см. раздел 3.4.
- `grow_blob_to_soft_edge` пересчитывает фон (blur/медиану/MAD) по всему кадру
  для КАЖДОГО пятна отдельно — избыточная работа при многих срезах на фото;
  не критично при типичных размерах фото, но можно вынести наружу и посчитать
  один раз на кадр.
- Утверждение "площадь не зависит от экспозиции" не подтверждено строго
  (адаптивный порог снижает, но не гарантированно устраняет зависимость) —
  предупреждение о разной выдержке сейчас показывается только для яркостных
  метрик.
